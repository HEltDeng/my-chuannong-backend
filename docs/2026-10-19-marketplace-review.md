# 二手好物审核联调记录（2026-10-19）

当前为本机内部预览，管理入口 `http://127.0.0.1:8792/admin/`。出售与求购使用同一审核流程，所有操作写入本产品独立 SQLite；未部署公网、未正式发布。

## 实际修改

- `marketplace.py`：独立承接二手模块，状态仅为 `PENDING`（待审核）、`PUBLISHED`（已发布）、`VIOLATION`（违规）。提交及编辑后重新审核；公共列表及非本人详情只允许已发布记录。
- 管理操作：待审核可通过或驳回；已发布可下架；任意状态可删除。驳回、下架必须填写非空原因（最多 500 字）。状态、原因、管理员审计和发布者通知在同一事务保存，重复操作和过时的详情拒绝提交。
- 删除移除发布记录及相关处理通知，并清理其图片；记录提交去重凭据，阻止同一旧请求重试后恢复已删除记录。它不是第四种业务状态。
- 通知按发布者隔离，保存信息标题、出售/求购类型、审核结果、原因、处理时间和已读状态。APP 的“处理通知”和“我的发布”可查看结果及原因。
- `admin/marketplace.js`、`marketplace.css`：搜索框内放大镜及回车搜索，校区、状态、出售/求购组合筛选；真实数据的手机布局预览，正文、品类、校区、发布者、联系方式、全部图片及处理原因均可查看。
- 图片保持比例，无固定高度裁切；详情和大图独立滚动，大图支持上一张、下一张。求购同样支持最多 4 张参考图片。
- Android 同步接口数据，连接失败不会回退到未审核的本机演示内容。前台页面每 10 秒同步，也支持主动刷新、重新进入及恢复前台同步。删除后清理列表、详情、发布记录和已打开的大图。

## 迁移

启动时一次性扩展旧数据库的状态约束。旧二手公开/完成记录因没有审核依据转为待审核；旧隐藏记录转为违规；旧删除记录移除并保留去重凭据。失物招领状态保持原有行为。迁移带事务与执行标记，重复启动不会把已审核记录重新改回待审核。本机执行前已创建独立备份。

## 实际验证

| 场景 | 结果 |
| --- | --- |
| 手机出售、求购提交 | 均待审核；公开列表不可见，其他账号不能读待审核详情 |
| 审核通过 | 两类均已发布；模拟器公开列表与详情可见 |
| 驳回、下架 | 空原因被前后端拦截；违规后公开列表不可见，手机显示信息标题、结果及具体原因 |
| 三种状态删除 | 两类均覆盖；后台、公开列表、本人记录、通知移除，重载 APP 不恢复；同一提交请求重试被拒绝 |
| 查看大图期间删除 | 同步后关闭大图，并清除详情 |
| 组合筛选 | 关键词（标题/正文）、校区、状态、类型组合通过；浏览器验证放大镜及回车 |
| 全部详情与图片 | 待审核、已发布、违规均可读；长图/宽图比例核对通过，多图切换、长正文、联系方式滚动通过 |
| 旧数据迁移、并发审核 | 迁移幂等、失物状态保留、过时审核拒绝通过 |

## 使用与边界

运行本仓库 `start-local.ps1`，模拟器执行 `adb reverse tcp:8792 tcp:8792`。进入 APP「服务 → 二手好物」，提交后在「我的」查看审核状态；管理后台处理后查看「处理通知」或点击刷新。

当前通知是 APP 内通知，退出 APP 后再次进入可读取持久通知；没有配置系统推送、短信或邮件。本地后台必须运行。远程真机、iOS、公网部署与系统推送未在此次本地 Android 联调中实现或验证。

可复测代码：后端 `tests/test_marketplace_review.py`；Android `tools/test_campus_online.cjs`、`tools/test_secondhand.cjs`、`MarketplaceReviewDeviceTest.kt`。隔离设备测试的启动命令及主机驱动见 Android 仓库 `docs/handoff/2026-10-19-marketplace-review.md`。
