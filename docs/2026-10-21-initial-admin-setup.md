# 所有者首次设置超级管理员

用户在 2026-10-21 明确要求通过公网后台自行填写初始超级管理员账号名和密码，并确认沿用现有权限模型：超级管理员管理全部平台账号、创建运营管理员；各运营管理员只访问其角色对应业务板块，不能自行提升权限。

初始生产引导仍使用仓库外随机临时凭据验证身份。新增 `admin_setup_required` 和 `admin_setup_completed_at`；新引导账号需要在已登录后的设置窗口填写账号名、新密码和确认密码。没有新增匿名注册超级管理员的入口。

已有库默认不要求重新设置。对本次只有唯一初始账号的干净库，通过 `manage.py require-initial-admin-setup <临时用户名>` 显式开启一次交接；已完成设置或已有其他账号时，该命令拒绝重新开放。

设置接口为 `GET/POST /api/v1/admin/account/setup`，仅在管理域名提供，必须持有启用中的初始超级管理员会话。设置前仅允许身份查询、退出和设置接口。保存时以事务原子更新用户名及密码哈希，保留用户 ID、角色和全部原权限，关闭设置入口并撤销该账号全部旧会话。密码不回传、不写入日志、Git 或明文配置。所有者随后用新凭据登录。

登录发放会话前再次通过 SQL 核对已验证的密码哈希，防止与设置并发的旧密码登录在撤销之后重新产生会话。跨站管理写入沿用生产 Origin 限制。设置请求另有频率限制。

新增隔离测试涵盖匿名/运营管理员/停用账号拒绝、未设置账号的模块限制、改名和旧会话撤销、无效输入回滚、重复/并发设置、旧密码并发登录、已有库不自动重置、显式引导命令边界与生产跨站拒绝。原生产运行测试增加了实际的引导、设置和新凭据登录流程；旧的“本地联调”页面文案断言更新为已上线的“校园运营后台”。

部署前备份数据库。所有真实账号名和新密码由用户在公网页面自行填写与提交，代理不代填新凭据。本机先前保存的临时凭据在用户完成设置后即失效。
