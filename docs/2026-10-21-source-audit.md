# 1.0.0 后台源码审计

本轮沿用现有后台及 Git 历史，完成源码审计、清洗、测试与私有仓库同步，不部署公网，不导入本机运营数据。完整结果见 [配套 Android 仓库审计报告](https://github.com/HEltDeng/my-chuannong-android/blob/codex/release-1.0.0/docs/audit/2026-10-21-release-1.0.0.md)。

修复生产 APK 校验的内网目标、重定向及无界下载风险：仅允许公网 HTTPS 443 直链，检查全部 DNS 结果并连接核对 IP，TLS 验证原域名，流式检查声明大小（最大 512 MiB）、摘要与读取期限。上传的版本元数据仍须通过原有发布门禁。升级并锁定 Pillow 13.0.0，处理上游已披露的图片解析漏洞。

干净源码副本使用新虚拟环境安装锁定依赖，97 项 unittest 全部通过，含生产入口、备份恢复及新增 8 项下载边界测试；4 个管理端 JS 语法检查通过。Python 5 个依赖复查无已知漏洞命中。Gitleaks 历史/提交扫描未检出密钥。Bandit 保留 57 条中等级提示（固定 SQL 拼接、目录权限、拒绝目标字面量），核对未确认新增可利用问题，不宣称警告归零。

默认演示数据入口已移除。合成夹具仅供测试；新副本没有本地 data/uploads/backups，真实运营库、上传文件、备份、日志、学校凭据和私钥均不进入 Git。既有真实数据未被删除。`.gitattributes` 固定换行，`tools/verify_checkout.py` 检查源码清单。

HTTPS 服务尚未部署；生产环境凭据、目录权限和原签名公开指纹需另行配置。Python lock 尚无逐制品 hash，测试通过不等于生产上线或供应链完整验收。客户端原 JKS 已在用户 Mac 的加密备份中定位，当前尚未解密或产出本次签名 APK。

同日后续：用户已提供原签名迁移包，客户端原 JKS 在仓库外恢复，私钥与历史证书核对通过。上文关于尚未取得签名的描述为源码审计时点记录；密钥及口令未上传，后台服务仍未部署。
